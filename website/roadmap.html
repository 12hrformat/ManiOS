Roadmap

From a bootable terminal to a public release. Foundation first, features second.

PHASE 0

Project Foundation

X Create GitHub repository
Make repository private during development
Establish final repository structure
Add LICENSE
X Add CONTRIBUTING.md
Add issue templates
Add pull request template
Define contribution rules
Define branch strategy
PHASE 1

Mani Linux Base System

Target: Oct 4

Goal: Boot into a functional terminal-based Linux system.

Produce first bootable ISO
Boot successfully in VM
Verify x86_64 architecture
Kernel loads correctly
Root filesystem mounts correctly
Init system starts correctly
Reach TTY/login prompt
Filesystem layout (/, /bin, /etc, /home, /usr, etc.)
User management & sudo
Networking & internet access
Package management foundation
VM testing & reproducible ISO builds
PHASE 2

Core Terminal Environment

Make the basic terminal experience usable.

Choose & configure shell
Core commands: ls, cd, cat, grep, find, etc.
System commands: ps, kill, uname, df, free
Networking commands: ip, ping, ss, DNS
PHASE 3

Networking

Mani Linux can connect to a network and access the internet.

Interface detection & configuration
DHCP & static IP
DNS & IPv4/IPv6
Internet connectivity & failure handling
PHASE 4

Package System

The charge package manager — sudo charge nmap installs, sudo charge down nmap removes, sudo recharge nmap updates. Update, install, remove, upgrade.

Package format & metadata
Repository & index
Install / remove / upgrade / search
Dependency resolution & verification
PHASE 5

Mani Security Toolkit

See Tools Page

Turn the functional Linux base into a security-focused OS.

Recon: Nmap, Amass, Subfinder, Masscan
Web: FFUF, Gobuster, SQLmap, OWASP ZAP
Network: Wireshark, tcpdump, Netcat
Password: Hashcat, John the Ripper
AD: Impacket, BloodHound
Wireless: Aircrack-ng, Kismet
RE: Ghidra, Radare2
Forensics & reporting tools
PHASES 6–12

Future Phases

Phase 6: Mani CLI — unified command-line experience
Phase 7: System configuration (hostname, locale, timezone, etc.)
Phase 8: GUI — desktop environment, branding, terminal theme
Phase 9: Security workflow — engagements, evidence, reporting
Phase 10: Testing & quality — VM + hardware testing
Phase 11: Documentation — guides, troubleshooting, FAQ
Phase 12: Public release — ISO, checksums, open repo
SPRINT

Current Sprint — Target: October 4

Functional TTY

Golden Rule

Do not build the GUI before the foundation works.

BOOT → TTY → FILESYSTEM → CORE COMMANDS → NETWORK → INTERNET → PACKAGE MANAGER → SECURITY TOOLS → GUI → MANI FEATURES → PUBLIC RELEASE
